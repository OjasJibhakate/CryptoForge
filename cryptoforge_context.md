⚡ CRYPTOFORGE v1.0
High-Frequency Institutional Scalping & Multi-Asset Execution Matrix

📖 Project Overview
CryptoForge is a fully autonomous, high-frequency algorithmic trading system built for the 1-minute cryptocurrency futures market. Instead of relying on lagging retail indicators (RSI, MACD), the system utilizes a Dual-Approval Architecture:

The Meta-Brain (LightGBM): Predicts kinetic breakouts using institutional order flow and inter-market momentum.

The Whale Veto Radar: Scans the live order book via REST API at the moment of execution to detect and avoid multi-million dollar spoofing walls.

🏗️ System Architecture (The 4 Pillars)
1. crypto_universe.py (The Radar)
Purpose: Dynamically scans the Binance Futures market to isolate the daily target universe.

Logic: Filters 250+ coins to find top-tier altcoins exhibiting > $250 Million 24h Volume and 5% - 15% optimal volatility.

Output: Returns a list of targets (e.g., ['BTCUSDT', 'ETHUSDT', 'HYPEUSDT', 'SPCXUSDT']) for the live bot to track.

2. crypto_metabrain.py (The ML Training Engine)
Purpose: The offline data-science pipeline that trains the core AI.

Feature Engineering: Extracts 15 non-correlated alpha features, including:

Whale Aggression Metrics: tbqav / qav (Taker Buy vs Total Volume) to detect hidden Iceberg orders.

Inter-Market Alpha: Cross-references BTC data with ETH data to detect systemic market momentum (eth_btc_ratio, btc_eth_momentum_diff).

Model: LightGBM Classifier with class_weight='balanced' and chronological splitting.

Output: Saves a serialized meta_brain_lgb.pkl file containing the decision trees and feature expectations.

3. crypto_live_bot.py (The Live Execution Core)
Purpose: The production paper-trading engine connecting to live market feeds.

Connection: Uses Binance's updated 2026 /market/stream WebSocket architecture.

Execution Flow: 1. Re-sweeps the universe & downloads 80 mins of cold-start historical data. 2. Listens for 1-minute candle closes across multiple assets simultaneously. 3. Triggers the .pkl Meta-Brain to generate a probability score. 4. If Probability > 70%, triggers the Whale Radar. 5. If no $2M+ limit walls exist, it executes the trade and logs it.

Safety Loops: Features an automatic 24-hour socket-reset interceptor to refresh memory buffers and dynamically swap out dead altcoins.

4. dashboard.py (The Analytics UI)
Purpose: A real-time Streamlit local web application.

Function: Ingests the crypto_live_trades.csv generated by the live bot. Displays active positions, resolved Win/Loss ratios, and provides a parameter optimization sandbox (Stress testing margin, leverage, and dynamic stop-loss zones).

🧮 Quantitative Mechanics & Math
The 0.50% Profit Target Strategy
CryptoForge executes on the 1-minute timeframe targeting rapid 0.50% micro-moves with a tight 0.50% stop-loss.

The Math: By compounding multiple 0.50% targets across a 6-asset satellite matrix, the system extracts systemic alpha while minimizing time-in-market exposure to flash crashes.

Fees: After a standard 0.10% round-trip exchange fee, the system nets roughly 0.40% pure profit per win, heavily amplified by 5x to 10x futures leverage.

The Precision-Recall Paradox
The ML model baseline achieves a ~28% out-of-sample precision on a 70% confidence threshold. In pure HFT (High-Frequency Trading), 1-minute market data is 75% noise. A 28% AI edge is highly institutional. The system achieves a positive expectancy not through a 90% AI win-rate, but by allowing the Live Order Book Whale Veto to filter out the false-positive AI signals caused by resting limit order manipulation (Spoofing).

## 🧮 3. Quantitative Mechanics & System Physics

### The 0.50% Scalp Matrix
* **Target:** 0.50% Take Profit | **Risk:** 0.50% Stop Loss.
* **Fees:** Assumes 0.10% round-trip exchange fees.
* **Logic:** 0.50% is a *kinetic strike*. It happens faster than whales can pull their limit orders. Holding for larger targets (like 1.00%) on a 1m chart exposes the bot to rapid mean-reversion crashes. 

### The AI Confidence Floor
* **Threshold:** `AI_CONFIDENCE_THRESHOLD = 0.70`
* **Logic:** The ML model must output a >70% probability of a bullish breakout. In HFT, 1-minute data is 75% noise. A 70% threshold is highly conservative and acts as the primary risk filter.

### The Whale Veto Radar
* **Threshold:** `WHALE_WALL_USD = 2000000` ($2 Million)
* **Logic:** Even if the AI outputs an 85% probability, the bot will REST-API ping the top 50 levels of the Binance order book. If there is a $2M+ Sell Wall sitting between the current price and the 0.50% target, the trade is explicitly aborted to prevent getting trapped in a spoofing dump.

## 🛠️ 4. Critical Engineering Patches (Historical Context)
*If future AI suggests changing these blocks, strictly forbid it. These were hard-fought bug fixes.*

### A. The Asynchronous Websocket Race Condition (The `.ffill()` Patch)
* **Problem:** Binance WebSockets stream asynchronously. If an altcoin candle arrived 50 milliseconds before the Ethereum baseline candle, the bot dropped the trade due to `how='inner'` merge failing.
* **Solution:** Merging was patched to `how='left'` with a `.ffill().bfill()` forward-fill block. This allows the bot to safely use the previous microsecond's ETH data if the network lags, preventing dropped trades.

### B. The Cross-Contamination Resolver Bug
* **Problem:** Early versions looped through *all* open positions whenever *any* coin closed, causing Bitcoin's price drops to falsely trigger Stop-Losses on unrelated altcoin positions (logging fake losses).
* **Solution:** The `ACTIVE_POSITIONS` resolver was strictly isolated. A trade's target/stop is *only* evaluated when its specific symbol's candle closes.

### C. The Limit-Order Accounting Leak
* **Problem:** The bot originally logged the *candle close price* as the win/loss price. 
* **Solution:** The `log_live_trade` function was patched to log the precise mathematical `pos["target"]` and `pos["stop"]`. This ensures the Omni-Matrix dashboard exactly mirrors live limit-order fills.

### D. The Empty-Data UI Shield
* **Problem:** Blanking the CSV file crashed the Streamlit dashboard with a `KeyError: 'status'`.
* **Solution:** A `pd.errors.EmptyDataError` shield was added to `dashboard.py`. If the file is deleted or blank, it gracefully waits and displays: *"Waiting for the bot to execute Trade #1..."*
